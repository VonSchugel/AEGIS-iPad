# Independent installation validation

Validation takes three bounded read-only connectivity samples. Every sample requires a singleton normal-mode profile, no discovery blockers and a successful numeric USB inventory containing exactly one Apple descriptor. The expected local device token must match; when omitted, the first valid singleton sample establishes the local binding. Connectivity alone never establishes jailbreak completion.

Authenticated probes require a native Linux or macOS host, an operator-supplied SSH identity file and existing `ssh`, `inetcat` and `idevice_id` utilities. WSL is excluded. Immediately before probing, `idevice_id -l` must return exactly one valid identifier whose digest matches the bound profile. Raw identifiers remain in transient memory and subprocess arguments; the runner must never log those arguments or raw streams.

The SSH `ProxyCommand` invokes the absolute, shell-quoted `inetcat` path with `-u <ephemeral identifier> -l <device SSH port>`. The port defaults to 44 when an identity is supplied. It means the port on the iPad. No network fallback or localhost forwarding listener is used. The [official inetcat manual](https://raw.githubusercontent.com/libimobiledevice/libusbmuxd/master/docs/inetcat.1) documents explicit device selection, USB-only selection and stdin/stdout transport suitable for ProxyCommand; inspected 2026-10-20. This is a moving upstream source, and installed-tool provenance/version must be verified separately.

SSH ignores user configuration with `-F /dev/null`, disables interactive authentication, uses the supplied identity and `StrictHostKeyChecking=yes`, and pins `HostKeyAlias=aegis-<local token>`. The operator must independently obtain the device's SSH host key and preconfigure that alias in `known_hosts`. Validation never accepts or adds a key automatically. A missing or mismatched pin leaves the installation unverified.

The token is SHA-256 of the lowercase, trimmed identifier supplied by the existing normal-mode USB interface. It is intentionally hidden in public JSON. An operator configuring a private host-key pin can inspect `DiscoveryAgent().discover()` locally through the Python API; do not publish its token or raw identifier. This application does not fetch an SSH host key blindly, install a device key or change a password. A protected backup and known-good recovery access should exist before that separate preparation.

The first fixed remote command selects an existing executable from `/var/jb/usr/sbin/sysctl`, `/usr/sbin/sysctl` and `/sbin/sysctl`, then compares `sysctl -n hw.machine` with the selected product identifier. Mismatch stops further probes. The remaining fixed commands check the rootless bootstrap tree, `dpkg`, its version and root command execution. Outputs and SSH diagnostics are discarded after evaluating those predicates. Missing sysctl, SSH or bootstrap components cannot produce a validated result.

`CORE_VALIDATED` requires every connectivity, USB reliability, device binding, hardware identity, SSH and bootstrap predicate to pass. Graphical package-manager operation, reboot persistence and long-term stability remain `UNKNOWN`. Validation does not pair, install keys or packages, change passwords, reboot, erase, restore or alter firmware. Such preparation requires a separate explicitly authorized operator-controlled experiment.

Fixture tests mock every physical transport. They verify token binding, singleton enforcement, explicit USB selection, shell quoting, host-key options, hardware mismatch, missing utilities, malformed identifiers, timeouts, structured errors and unverified outcomes. They provide software evidence, not proof of a successful installation on a physical iPad.
