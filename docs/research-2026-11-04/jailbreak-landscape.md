# Jailbreak and boot-chain landscape

Checked **2026-11-04**. Target: **iPad7,11 / iPad7,12**, Apple A10/T8010. This report is a new research snapshot; it does not widen the executable policy in `src/aegis/data/compatibility.json` or replace its pinned artifacts. Source details and reproductions are in [jailbreak-sources.json](jailbreak-sources.json).

The packaged compatibility snapshot retains its original **2026-10-20** base date. Only its Dopamine method metadata and directly related evidence entries were refreshed on **2026-11-04**, recorded under `component_refreshes`. The broader findings below are a research report, not a wholesale revalidation of every executable policy dependency.

## Decision

Keep the small, pinned **palera1n v2.4 rootless adapter** as the existing execution integration. Retain **Dopamine as a separately reviewed manual alternative**. Evaluate newer boot infrastructure in an independent research track before adapting it. There is no measured evidence here that replacing v2.4 with a fork improves iPad 7 reliability or speed.

The strongest current correction is freshness: **Dopamine 3.0.13**, released **2026-11-03**, supersedes the repository's 3.0.11 comparison. Its tagged README still documents **arm64 15.0–18.7.1**. The additional iOS 26 range is associated with A12/A13 in that README and supplies no new A10 eligibility. [Tagged README](https://github.com/opa334/Dopamine/blob/5b1d2c1c3bf54dd8e3641d29c60cd3a0c13cde88/README.md), [release notes](https://github.com/opa334/Dopamine/releases/tag/3.0.13).

No connected-device test was performed by this research track. Installed firmware, build, backup, actual USB transport and device identity remain **UNKNOWN** until fresh discovery establishes them.

## Evidence language

- **VERIFIED:** a local observation, such as remote-ref resolution or a source diff actually performed. It verifies only the stated observation.
- **DOCUMENTED:** an upstream support statement, release note or source implementation. It does not prove physical success.
- **EXPERIMENTAL:** an explicitly experimental implementation or an author-reported hardware result.
- **HYPOTHESIS:** an inference requiring a test.
- **UNKNOWN:** missing evidence or an unperformed check.

These reports use `DOCUMENTED`. Historical `SUPPORTED BY DOCUMENTATION` inputs remain accepted by the application and normalize to DOCUMENTED in typed evidence. Repeated claims from one project's README, website and release notes are related evidence.

## Target identity and boot-chain boundaries

The pinned libirecovery table maps **iPad7,11 → j171ap, board 0x1c, CPID 0x8010** and **iPad7,12 → j172ap, board 0x1e, CPID 0x8010**. This is **DOCUMENTED device-database evidence**; it does not replace observing the attached target. [Pinned database](https://github.com/libimobiledevice/libirecovery/blob/046344f7fe4413e42e71046a34230850be3f758a/src/libirecovery.c).

Apple describes an immutable Boot ROM verifying iBoot, which verifies the operating-system kernel; its additional LLB stage applies to A9 and earlier. Apple also describes separate Secure Enclave and cellular baseband boot verification. Consequently, AP boot-ROM control must not be promoted to control over SEP, baseband, storage decryption, bootstrap completion or Linux peripheral support. [Apple boot-process documentation](https://support.apple.com/nl-nl/guide/security/secb3000f149/web).

A11 passcode/reset caveats on palera1n's README concern A11 devices. They must not be copied into A10 instructions as a target requirement. The current installation guide also describes USB cable/host issues and rejects ordinary Windows VMs/WSL. These are upstream warnings, not measured AEGIS failure rates. [Tagged palera1n README](https://github.com/palera1n/palera1n/blob/3ba32c40dbd90b9bcff1a71b5f9ee26c3388b0ad/README.md), [installation guide](https://docs.palera.in/installing-palera1n/).

## Forks and changes that alter the integration decision

**palera1n V3.X:** PR #765 describes replacing libimobiledevice/libirecovery usage with Rust `idevice`, configurable exploit libraries, and Windows compilation using libopenra1n/libusbK. Its macOS/Linux release composition includes a closed-source exploit implementation, according to the author. The PR was open when checked. Build capability on this branch is **EXPERIMENTAL evidence**, not evidence that v2.4 supports Windows or that the documented WSL restriction has disappeared. The beta.2 release's internal reliability claim has no supplied comparative measurement; its bug fixes and changed flags need source review and representative adapter tests. [PR #765](https://github.com/palera1n/palera1n/pull/765), [beta.2 notes](https://github.com/palera1n/palera1n/releases/tag/v3.0.0-beta.2).

**palera1n PongoOS:** the inspected latest fork commit disables a `root_livefs` patch as unnecessary. This is a concrete KPF change, not an A10 success-rate improvement. Its license file distinguishes the MIT whole-project license from third-party terms, including the USB driver's Apache terms; preserve that composition if source is reused. Reuse an upstream release's coherent dependency set before cherry-picking isolated patches. [commit](https://github.com/palera1n/PongoOS/commit/e98323f8a09abd80fc4cbcd74dee023b91a1ec22), [license composition](https://github.com/palera1n/PongoOS/blob/e98323f8a09abd80fc4cbcd74dee023b91a1ec22/LICENSE.md).

**Gaster comparison actually performed — VERIFIED source observations:** compared original `7fffffff38a1bed1cdc1c5bae0df70f14395129b` with palera1n fork `20958256a4706b6396e2d9ee9ca742618459980b` using Git. The two-snapshot diff has **5 changed files, 153 insertions, 53 deletions**. It adds build provenance/CI/static-build support and changes USB timing/spray logic. It also removes the original's positive USB timeout check; modulo arithmetic with that timeout remains. **HYPOTHESIS:** setting the fork's `USB_TIMEOUT=0` can reach a zero divisor. No exploit or binary was built or executed to test it. The fork snapshot is dated 2023-01-21 while the original is dated 2023-02-02; this fork is not newer than the compared original. Diff size is not a performance metric. [fork source](https://github.com/palera1n/gaster/blob/20958256a4706b6396e2d9ee9ca742618459980b/gaster.c), [fork Makefile](https://github.com/palera1n/gaster/blob/20958256a4706b6396e2d9ee9ca742618459980b/Makefile).

**roothide/Palera1n-roothide:** release 1.0 dated 2026-10-25 claims broad iPadOS 17/18 applicability. Its wrapper combines modified Pongo/KPF, jbinit, host packaging and an additional on-device application path. This adds integration and artifact review work. The inspected wrapper root did not expose a top-level license, and the entire linked composition was not audited. **Do not select it from its broad support claim:** no reproducible target-specific reliability comparison was found. [README](https://github.com/roothide/Palera1n-roothide/tree/a4f4365f560ec905e59df5a48be112fecf818a80), [release history](https://github.com/roothide/Palera1n-roothide/releases).

## Contradictory evidence and freshness

An issue on the actual iPad 7 reports a missing boot patch on iPadOS 18.4 with an older release. It corroborates why a checkm8-capable SoC is insufficient for package compatibility. It is **EXPERIMENTAL, user-reported evidence**, not a current v2.4 failure result; the later v2.2 release explicitly reports 18.4 support. [target report #600](https://github.com/palera1n/palera1n/issues/600), [related tracker #598](https://github.com/palera1n/palera1n/issues/598).

The live palera1n guide still suggests older Dopamine version ranges, while Dopamine's tagged README documents a wider arm64 range. Dopamine's website also groups architectures more broadly than its tagged README. Prefer the versioned package's architecture-specific evidence and resolve installation prerequisites separately; do not merge the broadest claims from different pages. [guide](https://docs.palera.in/installing-palera1n/), [Dopamine website](https://ellekit.space/dopamine/), [tagged README](https://github.com/opa334/Dopamine/blob/5b1d2c1c3bf54dd8e3641d29c60cd3a0c13cde88/README.md).

Dopamine 3.0.7's release documents a prior kernel-write/update defect; 3.0.13 documents a process-spawn fix and snapshot redirection changes. These notes establish maintenance activity and relevant regressions, not an independently demonstrated absence of defects. [3.0.7](https://github.com/opa334/Dopamine/releases/tag/3.0.7), [3.0.13](https://github.com/opa334/Dopamine/releases/tag/3.0.13).

## Prioritized next experiments and acceptance

1. **Fresh read-only discovery:** obtain one device's product type, release/build, mode and host transport. Pass only if identity is unambiguous; unavailable tools produce UNKNOWN rather than fixture-derived identity.
2. **Offline compatibility regression:** exercise supported/rejected boundaries, prerelease/build mismatch, host architecture and multiple-device fixtures. No support expansion follows from this report alone.
3. **Source/artifact review for any new adapter:** pin complete source and dependency revisions, inspect command/environment differences, validate release checksums, and run subprocess/simulation tests. Pass only when unsupported commands cannot be constructed and previous safety tests pass.
4. **Operator-approved hardware experiment:** only after target, backup and artifact gates pass on a supported native host. Predeclare identity retention, bounded exit/timeout, independent bootstrap validation and recovery stopping conditions. Each attempt needs authorization; record unsuccessful and partial results.
5. **Fair implementation comparison, if still justified:** hold device/build, cable, USB controller, host and readiness procedure constant; record successful validated boots per authorized attempt, elapsed time and failure stage. Separate operator time from adapter time. Report sample size and uncertainty. None of these physical measurements has been collected.

## Provenance and access gaps

Git remote refs and the gaster source comparison were actually collected locally. Public web pages and raw source were read. No standalone tool release, IPA, firmware, driver or host boot image was downloaded or run by this track. A shallow gaster repository comparison resides in the workspace's ignored `work/research-20261104-gaster`; its Git objects include upstream's tracked payload blobs. Those blobs were never loaded on hardware, and no upstream build scripts or tools were executed.

GitHub's unauthenticated API became rate-limited. Some GitHub comparison/tree pages were restricted and Apple English documentation returned HTTP 429; the Dutch-hosted English-text Apple security page remained accessible. Raw pinned source, Git remote refs and individual commit pages supplied the evidence recorded here. This is a prioritized investigation, not an exhaustive audit of hundreds of forks or a verification of their binary releases. License entries identify inspected source notices; the complete release dependency chain still needs review before redistribution.
