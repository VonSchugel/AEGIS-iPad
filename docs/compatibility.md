The palera1n ceiling is deliberately **18.4.0**, excluding 18.4.1 and later until exact-version evidence is reviewed. It is an AEGIS policy, not a statement of upstream's maximum. Its [pinned manual](https://github.com/palera1n/palera1n/blob/3ba32c40dbd90b9bcff1a71b5f9ee26c3388b0ad/docs/palera1n.1) contains a broad description and an older supported-device version paragraph. The engine avoids extending a broad support slogan to every later release. Apple lists [18.7.10 for iPad 7 on 2026-08-17](https://support.apple.com/en-us/100100); firmware availability does not establish jailbreak support.

The [palera1n installation guide](https://docs.palera.in/installing-palera1n/) requires native Linux/macOS and rejects WSL and ordinary Windows VMs. Windows can perform read-only discovery when appropriate Apple drivers/utilities exist, but the execution gate blocks it. A separately booted supported operating system requires independent preparation; AEGIS never writes a USB boot image. The project additionally limits execution to reviewed x86_64/arm64 host artifacts. Missing WSL status, unknown host architecture or unsupported device state blocks eligibility.

The engine accepts only release-form numeric versions and release-style build identifiers, checks build-train consistency, and requires a known normal/recovery/DFU mode. **It does not establish that an arbitrary version/build pair exists in Apple's release catalog**. Real execution must bind the profile to fresh observations; supplied fixtures establish software behavior only. Eligibility still requires backup, dependency, provenance, approval and device-identity gates.

For palera1n 2.4 the minimal reviewed rootless command is `palera1n -l`. It is interactive: upstream owns DFU guidance after approval. Its subprocess return code is insufficient evidence of bootstrap installation. The loader/package-manager stage and validation remain separate. Rootful/fakefs, overrides, custom kernel arguments, demotion and Pongo shells are outside ordinary installation scope. Rebooting a semi-tethered installation normally returns to stock operation; re-entering the jailbreak requires the supported host tool again. [Pinned command and behavior reference](https://github.com/palera1n/palera1n/blob/3ba32c40dbd90b9bcff1a71b5f9ee26c3388b0ad/docs/palera1n.1).

Official [2.4 release asset metadata](https://github.com/palera1n/palera1n/releases/expanded_assets/v2.4) provides SHA256 digests recorded in the packaged JSON. These identify exact standalone Linux/macOS release assets, not `.deb` packages or rebuilt binaries. No upstream binary was downloaded or executed during research. Match the selected artifact's architecture and digest before any invocation, including a version probe. Integrity metadata is not an independent audit.

Dopamine's current range differs from older guide text. Its [ClearSword metadata](https://github.com/opa334/Dopamine/blob/3.0.11/Application/Dopamine/Exploits/ClearSword/Info.plist) additionally declares kernel-exploit requirements; an individual exploit range cannot replace full package checks. The [3.0.7 release](https://github.com/opa334/Dopamine/releases/tag/3.0.7) addresses a kernel-write/update defect and older 3.0–3.0.6 releases carry an upstream warning. The project records the current stable comparison without installing an IPA.

Every machine-readable finding in `src/aegis/data/compatibility.json` includes its question, source/revision, observation, classification, confidence, limitations, reproduction and next investigation. Repeated source claims are not independent experiments. Source pages that could not be pinned are identified explicitly. Network access from the shell was unavailable; browsing supplied the cited source evidence.
